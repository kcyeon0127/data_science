# Challenge Submission Checklist

This folder summarises the official evaluation policy and what we need to deliver for the CTR challenge.

## 📜 Policy (번역)
- 공개된 다른 구현체를 사용할 수 있으나, 반드시 출처를 명시해야 합니다. 출처를 밝히지 않으면 **20점 감점**됩니다.
- 평가 항목
  - **Novelty (20점)**: 베이스라인 대비 어떤 새로운 시도를 했는가?
  - **EDA 수행 여부 (10점)**: 데이터 탐색을 했는가?
  - **Feature selection 설명 (5점)**: 사용한 피처와 선택 이유를 설명했는가?
  - **Model selection 설명 (5점)**: 모델 선택 이유를 설명했는가?
  - **랭킹 점수**: 챌린지 순위(n)에 따라 추가 점수 부여

### Novelty(20점) 세부 배점
| 항목 | 점수 |
| --- | --- |
| 모델 변경 | 2점 |
| 피처 분석 및 신규 피처 선택 | 3~6점 |
| 앙상블 수행 | 2점 |
| 하이퍼파라미터 변경 | 3점 |
| WOW 요소 (창의적인 시도) | 0~10점 |

## ✅ 우리가 해야 할 일
1. **출처 명시**: 외부 구현을 참고했다면 코드/보고서에 반드시 출처를 남긴다.
2. **EDA 수행**: 데이터 분포, 이상치, 시퀀스 길이 등을 탐색하고 시각화/요약을 준비한다.
3. **Feature Selection 설명**: 기본 피처 외에 추가한 파생 피처(예: LSTM/Transformer 임베딩, 타깃 인코딩 등)를 선정한 이유를 정리한다.
4. **Model Selection 설명**: 선택한 모델 구조와 기대 효과를 문서화한다.
5. **Novelty 채우기**: 모델 변경, 신규 피처, 앙상블, 하이퍼파라미터 튜닝, WOW 요소를 적극 시도한다.
6. **실험 로그 관리**: 실험별 설정과 점수를 기록해 재현성과 랭킹 근거를 확보한다.
7. **최종 보고/발표 정리**: 위 내용을 바탕으로 보고서(또는 슬라이드)를 작성하고, 제출 파일(`submission_*.csv`)과 코드 버전을 관리한다.

## 📂 폴더 구성
- `README.md` (본 문서)
- `evaluation_checklist.py` : 실행하면 체크리스트가 출력되는 간단한 스크립트
- `models/` : 하이브리드 모델 예시 스크립트 (예: `xg_lstm.py`, `xg_trans.py`)
